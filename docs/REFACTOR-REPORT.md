# تقرير إعادة الهيكلة — سند تعز

**تاريخ النسخة:** 2026-11-12
**نوع التسليم:** نسخة مصدر معاد تنظيمها، مع الحفاظ على الوظائف والمسارات الحالية قدر الإمكان.

## 1. إعادة فصل الواجهة

تم تفكيك الملف السابق `artifacts/sanad-taiz/src/App.tsx` إلى:

- `App.tsx`: تركيب التطبيق، مزودات الحالة، تعريف المسارات، وحدود الأخطاء.
- `pages/`: 12 وحدة للصفحات والمناطق الوظيفية (الرئيسية، المسارات، التقييمات، المساحة الآمنة، المكتبة، الحجز، الإدارة، تسجيل الدخول، القصص، المساعدة والخصوصية، والعناية الذاتية).
- `components/layout.tsx`: الغلاف العام والتنقل والتحكم بالثيم.
- `components/page-ui.tsx`: عناصر واجهة الصفحات المشتركة وحالات التحميل والخطأ والفراغ.
- `components/home-widgets.tsx`: مكونات المزاج والترويج والعناية الذاتية.
- `components/media.tsx`: بطاقة الموارد واختيار صورة المحتوى.
- `components/admin-editors.tsx`: محررات الإدارة ومحرر جهات المساعدة.
- `components/support-ui.tsx`: عناصر الدعم العاجل والخروج السريع.

انخفض `App.tsx` من نحو 2,569 سطراً في النسخة السابقة إلى نحو 74 سطراً، وأصبحت الصفحات وحدات مستقلة قابلة للصيانة. أضيف التحميل الكسول `React.lazy` للصفحات حتى لا يلزم تحميل جميع صفحات المنصة عند فتح الصفحة الرئيسية.

## 2. تنظيم CSS

تم الإبقاء على `index.css` كنقطة إعداد Tailwind والخطوط والمتغيرات الأساسية، ثم تقسيم بقية القواعد إلى ملفات مرتبة تُحمّل بالتتابع من `main.tsx`:

1. `styles/brand-foundation.css`
2. `styles/global-components.css`
3. `styles/content-pages.css`
4. `styles/admin-overrides.css`

تم الحفاظ على ترتيب القواعد الأصلي داخل الملفات لتقليل مخاطر تغير الـ cascade أو المظهر. كما أزيل تكرار قديم لمجموعة شارات التقييمات `promo-badges` بعد الإبقاء على مجموعة التصريحات النهائية الفعالة.

> لم تُحذف قواعد CSS لمجرد تشابه المحددات؛ فبعض التكرارات جزء من تعديلات الوضع الليلي أو تجاوبات الشاشات، وحذفها دون اختبار مرئي قد يغير التصميم.

## 3. الحفاظ على الوظائف

- الإبقاء على مسارات Wouter الحالية.
- الإبقاء على Query Client ومزودات Toast وConfirm وTooltip وError Boundary.
- تحويل صفحات المسارات إلى تحميل كسول مع شاشة تحميل احتياطية.
- استخدام `useQueryClient()` داخل صفحة الدخول لمسح ذاكرة الاستعلامات بعد تسجيل الدخول، بدلاً من الاعتماد على متغير خارج وحدة الصفحة.
- لم تُجرَ تغييرات على مخطط PostgreSQL أو بياناته في هذه المرحلة.

## 4. نتائج التحقق المنفذ

| الفحص | النتيجة |

## 5. اختبار البناء الكامل — قيد التحقق

تمت محاولة تثبيت الحزم باستخدام `pnpm install --frozen-lockfile`، لكن بيئة إعداد هذه النسخة لم تتمكن من الوصول إلى `registry.npmjs.org` بسبب خطأ DNS (`EAI_AGAIN`). لذلك لم يكن ممكناً تشغيل `pnpm run typecheck` أو `pnpm run build` في هذه البيئة.

هذا يعني أن الفحوص أعلاه تؤكد سلامة الصياغة والاستيرادات المحلية وملفات CSS، لكنها **لا تعادل نجاح بناء Vite أو اختبار تشغيل المتصفح**. يجب تنفيذ أوامر التحقق التالية بعد فك الضغط في Termux أو جهاز متصل بالإنترنت:

```bash
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm run build
```

ثم تشغيل الواجهة والخادم واختبار المسارات وتسجيل الدخول والحجز وعمليات لوحة الإدارة ورفع الصور فعلياً.

## 6. تشغيل المشروع

من مجلد المشروع الرئيسي:

```bash
cp .env.example .env
# عدّل قيم البيئة محلياً ولا تشارك ملف .env
pnpm install --frozen-lockfile
pnpm --filter @workspace/db run push
pnpm --filter @workspace/api-server run dev
```

وفي نافذة طرفية ثانية:

```bash
pnpm --filter @workspace/sanad-taiz run dev
```

راجع `README-TERMUX-AR.md` و`TERMUX-GUIDE.md` لتفاصيل البيئة الخاصة بالمشروع.

## 7. حدود هذه النسخة

هذه نسخة إعادة هيكلة مصدرية مكتملة من ناحية فصل صفحات App وتنظيم CSS والتحميل الكسول. لكنها لا تُعد اعتماداً نهائياً للإنتاج قبل نجاح التثبيت والبناء والاختبارات الوظيفية في بيئة المشروع، خصوصاً أن شبكة بيئة الإعداد منعت تنزيل الاعتماديات.
