# سَنَد تعز — دليل التشغيل والإصلاح في Termux

المشروع يتكون من واجهتين تعملان معاً:
- الواجهة: React + Vite على المنفذ `5173`.
- الخادم: Express API على المنفذ `5000`.
- قاعدة البيانات: PostgreSQL باستخدام Drizzle ORM.
- تسجيل الدخول ولوحة الإدارة: نظام داخلي بالبريد وكلمة المرور مع جلسات آمنة داخل PostgreSQL.

## 1) المتطلبات

يفضّل Node.js 24 (ويمكن تجربة Node.js 22)، وGit وpnpm. في Termux:

```bash
pkg update -y && pkg upgrade -y
pkg install -y nodejs-lts git python make clang pkg-config
npm install -g pnpm
node -v
pnpm -v
```

## 2) فك المشروع وتثبيت الحزم

ضع ملف ZIP في مجلد Download ثم نفّذ (عدّل اسم الملف فقط إذا اختلف):

```bash
termux-setup-storage
cd ~/
mkdir -p sanad-taiz
cd sanad-taiz
unzip -o /sdcard/Download/snd-taaz-mnS-ldaam-fixed.zip
cd snd-taaz-mnS-ldaam
pnpm install
```

إذا كان المجلد موجوداً بالفعل، ادخل إلى مجلد المشروع مباشرة ولا تفكّه فوق نسخة تعمل قبل أخذ نسخة احتياطية.

## 3) إعداد البيئة وقاعدة البيانات والمصادقة

```bash
cp .env.example .env
nano .env
```

املأ القيم التالية بقيم حقيقية:
- `DATABASE_URL`: رابط PostgreSQL كامل. يجب أن تكون قاعدة البيانات قابلة للوصول من الهاتف، وأن يدعم الرابط SSL عند الحاجة.
- `ADMIN_EMAIL` و`ADMIN_PASSWORD`: ينشئ الخادم حساب المدير الأول تلقائياً عند أول تشغيل. كلمة المرور 12 حرفاً على الأقل.
- لا يحتاج المشروع إلى Clerk أو أي مفاتيح مصادقة خارجية.
- `SESSION_SECRET`: سر عشوائي طويل وثابت للجلسات؛ أنشئه بالأمر `openssl rand -hex 32`، واحتفظ به ما دامت هناك جلسات أو بيانات قديمة مشفرة بالمفتاح السابق.
- `BOOKING_ENCRYPTION_KEY`: سر عشوائي مستقل لتشفير بيانات التواصل بالحجوزات؛ أنشئه بقيمة منفصلة عبر `openssl rand -hex 32` ولا تغيّره دون خطة تدوير/إعادة تشفير.
- `COOKIE_SECURE`: اتركه فارغاً أو `true` على HTTPS؛ `false` يُقبل فقط حين `NODE_ENV=development` عند التشغيل المحلي عبر HTTP. لا تستخدم `false` على موقع منشور أو معاينة HTTPS.
- `CORS_ORIGINS`: في الإنتاج أدرج الأصل الدقيق للواجهة. يتطلب الخادم هذا الأصل لطلبات `POST` و`PUT` و`PATCH` و`DELETE` كدفاع CSRF؛ أدرج أصل معاينة HTTPS إذا شغّلت API فيها.

**مهم:** لا يمكن تشغيل تسجيل الدخول أو لوحة الإدارة ببيانات حساب المدير الأول الوهمية. ولا يمكن تشغيل بيانات المنصة من دون PostgreSQL حقيقي. لا ترسل ملف `.env` أو المفاتيح السرية إلى أي شخص.
بدء API ينفّذ seed لمحتوى أولي، وقد ينشئ مديراً إذا ضُبطت بياناته؛ راجع المخطط والسلوك وخذ نسخة احتياطية قبل ربط قاعدة فعلية.

## 4) إنشاء جداول قاعدة البيانات

من جذر المشروع:

```bash
set -a
. ./.env
set +a
pnpm --filter @workspace/db run push
```

راجع مخطط قاعدة البيانات قبل استخدام `push` على قاعدة بيانات إنتاجية؛ لا تستخدم `push-force` على بيانات مهمة.

## 5) فحص الأنواع وبناء المشروع

```bash
pnpm --filter @workspace/api-server run typecheck
pnpm --filter @workspace/sanad-taiz run typecheck
pnpm --filter @workspace/api-server run build
pnpm --filter @workspace/sanad-taiz run build
```

## 6) التشغيل — جلستان في Termux

افتح جلستين (أو نافذتين) داخل Termux.

**الجلسة الأولى — الخادم وقاعدة البيانات:**

```bash
cd ~/sanad-taiz/snd-taaz-mnS-ldaam
set -a; . ./.env; set +a
pnpm --filter @workspace/api-server run start
```

**الجلسة الثانية — الواجهة:**

```bash
cd ~/sanad-taiz/snd-taaz-mnS-ldaam
set -a; . ./.env; set +a
pnpm --filter @workspace/sanad-taiz run dev
```

افتح في متصفح الهاتف:
`http://127.0.0.1:5173`

يجب أن يعمل الخادم على:
`http://127.0.0.1:5000/api/healthz`

إذا أردت الوصول من جهاز آخر على نفس شبكة Wi-Fi استخدم عنوان IP للهاتف بدلاً من `127.0.0.1`، مع إبقاء المنفذين مفتوحين محلياً.

## 7) تسجيل الدخول إلى لوحة الإدارة

بعد تشغيل الخادم، افتح `http://127.0.0.1:5173/sign-in` وسجّل الدخول باستخدام `ADMIN_EMAIL` و`ADMIN_PASSWORD` اللذين وضعتهما في `.env`. لا توجد صفحة تسجيل عامة؛ إنشاء حساب المدير يتم من متغيرات البيئة عند أول تشغيل فقط.

## 8) اختبارات سريعة عند ظهور خطأ

```bash
# فحص استجابة API
curl -i http://127.0.0.1:5000/api/healthz

# التأكد من المنافذ
ss -ltn

# إصدارات الأدوات
node -v
pnpm -v

# عرض ملفات الإعداد دون كشف الأسرار
ls -la .env .env.example
```

## إصلاحات هذه النسخة

- جعل إعدادات Vite تعمل افتراضياً دون اشتراط متغيرات `PORT` و`BASE_PATH` من Replit.
- فصل منفذ الواجهة `VITE_PORT` عن منفذ API `PORT`.
- إضافة Proxy لمسارات `/api` من Vite إلى Express؛ كان غائباً، وبالتالي كانت طلبات الواجهة تفشل عند تشغيل الخادمين منفصلين محلياً.
- جعل Vite يقرأ ملف البيئة من جذر المشروع، وليس من مجلد الواجهة فقط.
- إضافة `.env.example` ودليل تشغيل Termux.
- استبدال Clerk بنظام دخول داخلي: تخزين كلمات المرور بتجزئة scrypt، جلسات عشوائية مخزنة كتجزئة في PostgreSQL، Cookie من نوع HttpOnly، وتقييد محاولات تسجيل الدخول.
- إضافة جداول المستخدمين والجلسات وإنشاء حساب المدير الأول من `ADMIN_EMAIL` و`ADMIN_PASSWORD` عند بدء الخادم.
- إزالة حزم Clerk وصفحات تسجيله ووسيط البروكسي الخاص به.

## حدود الفحص الحالي

تم تعديل ملفات المصادقة والواجهة والخادم والمخطط، والتحقق من بنية ملفات JSON/YAML وخلو ملفات المصدر من مراجع Clerk. لم أتمكن من تثبيت الحزم أو تنفيذ TypeScript/build في بيئة الفحص بسبب تعذر الوصول إلى سجل npm؛ لذلك يلزم تنفيذ أوامر الفحص في Termux قبل اعتماد التشغيل النهائي.
